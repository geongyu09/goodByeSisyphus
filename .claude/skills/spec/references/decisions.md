- 새 결정은 맨 아래에 번호를 이어 붙인다. 번호는 다시 쓰지 않는다.

### D-4. Notion 재시도는 SDK 내장 기능만 쓴다 (2026-10-15)
- 상태: 확정
- 결정: 사용자
- 내용: 직접 만든 `withRetry` 래퍼를 없애고, 클라이언트에 `retry: { maxRetries: 3 }`를 넣어 SDK 재시도만 쓴다.
- 이유: 설치된 `@notionhq/client` 5.27은 기본으로 429·529를 2회 자동 재시도한다(`Retry-After`를 따르고, 헤더가 없으면 지수 백오프와 지터). 문서의 `withRetry`(4회)로 감싸면 429 한 번에 요청이 최대 12번(4×3) 나간다. SDK는 500·503을 GET·DELETE에서만 재시도하므로, 2-4에서 말한 쓰기 요청 중복 저장도 막아 준다. `maxRetries: 3`은 예전 `withRetry`의 총 시도 횟수(4번)와 맞춘 값이다.
- 검토한 대안: (1) `withRetry`를 유지하고 SDK에 `retry: false`를 준다. (2) 문서 그대로 두고 이중 재시도를 감수한다.
- 바뀐 곳: 문서 `data-layer.md` 4-1·4-2, `server-actions.md` 6-2, `nextjs-setup.md` 3-4, `dev-order-and-limits.md` 11장. 로드맵 Phase 1 첫 작업. 코드 `lib/notion.ts`.

### D-7. 성공한 쓰기를 서버 데이터 위에 다시 적용한다 (2026-10-15)
- 상태: 확정
- 결정: Claude (사용자 확인 전)
- 내용: `components/Board.tsx`는 7-2처럼 `useOptimistic`으로 먼저 보여 주고, Server Action이 성공하면 그 쓰기(메모 추가, 스티커 붙이기·떼기)를 클라이언트 상태 `saved`에 쌓아 `initialNotes` 위에 다시 적용한다. 적용 함수는 여러 번 적용해도 결과가 같아서, 서버 데이터가 따라잡으면 그대로 겹친다. 새로고침하면 `saved`는 사라진다.
- 이유: `useOptimistic` 값은 transition이 끝나면 원래 값으로 돌아간다. 스티커 액션은 `revalidateTag('board', 'max')`라서 액션 응답에 오래된 캐시가 실려 오고, 7-2 코드 그대로면 붙인 스티커가 잠깐 보였다가 사라진다. Notion 조회가 방금 만든 메모를 늦게 돌려줄 때도 같은 일이 생긴다. 프로토타입의 `added`·`placed`가 하던 역할을 실제 id로 이어 받은 것이다.
- 검토한 대안: (1) 7-2 코드 그대로 둔다. 붙인 스티커가 사라졌다가 30초 안팎 뒤에 다시 보인다. (2) 스티커도 `updateTag`를 쓴다. 쓰기마다 Notion 전체 조회가 일어나 2-4 요청 한도를 빨리 쓴다.
- 바뀐 곳: 코드 `components/Board.tsx`. 문서 7-2 코드 예시는 아직 `useOptimistic`만 보여 주므로 문서와 코드가 다르다. 문서를 고치려면 사용자 확인이 필요하다.

### D-13. 프로토타입의 테스트 데이터 규칙을 실제 데이터에 맞춘다 (2026-10-15)
- 상태: 확정
- 결정: Claude (사용자 확인 전)
- 내용: 프로토타입이 쓰던 `order` 대신 Notion `created_time`(`createdAt`)으로 정렬한다. 최신순은 내림차순, 오래된순은 그 반대, 스티커 많은 순은 개수가 같으면 최신순, 무작위는 최신순으로 늘어놓은 뒤 `rng(seed)`로 섞는다. "붙이는 사람" 선택 상자를 지운 뒤에도 안내 문구는 프로토타입 기본값 `나`를 그대로 써서 "나 · 포스트잇을 누르면 …", "이 포스트잇에는 아직 나의 스티커가 없어요."로 둔다.
- 이유: 7-3은 "`base(count)` 대신 `getBoard()` 데이터"라고만 하고 정렬 기준을 정하지 않는다. `created_time`은 분 단위라 같은 분에 쓴 메모끼리는 Notion이 돌려준 순서를 따른다.
- 검토한 대안: 안내 문구에서 `나 · `를 뺀다.
- 바뀐 곳: 코드 `components/Board.tsx`, `components/StickerDock.tsx`.
