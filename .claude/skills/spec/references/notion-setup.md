## 2. Notion 쪽 준비

### 2-1. 연결(Connection) 만들기

Notion은 예전에 "integration"이라고 부르던 것을 지금 개발자 포털에서 "connection"이라고 부르며, 만드는 순서는 아래와 같습니다.

1. `app.notion.com/developers/connections`에서 새 연결을 만들고, 사용할 워크스페이스를 고릅니다. 연결은 **워크스페이스 소유자만** 만들 수 있기 때문에, 우아한테크코스 공용 워크스페이스에 권한이 없다면 개인 워크스페이스를 하나 만들어서 쓰는 편이 빠릅니다.
2. 연결의 **Configuration** 탭에서 API 토큰을 복사해 `.env.local`에 넣고, 코드나 Git에는 절대 올리지 않습니다.
3. 데이터베이스를 담을 페이지를 열고 오른쪽 위 `•••` 메뉴의 **Add connections**에서 방금 만든 연결을 추가해야 API가 해당 페이지와 하위 데이터베이스에 접근할 수 있으며, 추가하지 않은 페이지를 요청하면 오류가 납니다.

### 2-2. 데이터베이스와 데이터 소스

Notion API `2025-09-03` 버전부터 데이터베이스는 여러 개의 **데이터 소스**를 담는 그릇이 되었고, 속성(스키마)과 조회는 데이터 소스 단위로 바뀌었습니다. 그래서 코드에서는 `database_id`가 아니라 `data_source_id`를 써야 하며, 예전 블로그 글에 나오는 `notion.databases.query`는 SDK v5에서 제거되었으므로 `notion.dataSources.query`를 사용합니다.

`data_source_id`는 Notion 앱에서 데이터베이스 설정 → **Manage data sources** → **Copy data source ID**로 복사하거나, 코드에서 `GET /v1/databases/{database_id}` 응답의 `data_sources[].id`로 얻을 수 있습니다.

### 2-3. 속성 스키마

**Notes** 데이터베이스는 메모 한 장을 한 행으로 저장합니다.

| 속성 이름 | 타입 | 설명 |
| --- | --- | --- |
| `nick` | Title | 보내는 사람 닉네임 (20자 이하) |
| `msg` | Text | 메시지 본문 (500자 이하) |
| `color` | Number | 메모 색 인덱스 0~3 (노랑, 분홍, 초록, 파랑) |
| `authorKey` | Text | 작성자 식별 키 (5장 참고) |
| `hidden` | Checkbox | 운영자가 숨길 메모에 체크 |

작성 시각은 페이지마다 자동으로 붙는 `created_time`을 쓰면 되기 때문에 따로 속성을 만들지 않아도 됩니다.

**Stickers** 데이터베이스는 "어떤 사람이 어떤 메모에 붙인 스티커 하나"를 한 행으로 저장합니다.

| 속성 이름 | 타입 | 설명 |
| --- | --- | --- |
| `key` | Title | `${noteId}:${authorKey}` 형태의 고유 키 |
| `note` | Relation → Notes | 스티커가 붙은 메모 |
| `authorKey` | Text | 붙인 사람의 식별 키 |
| `type` | Number | 스티커 종류 0~7 (하트, 별, 네잎클로버 등) |
| `x`, `y` | Number | 메모 안에서의 위치(%) |
| `rot` | Number | 회전 각도 |

메모의 기울기와 핀 색은 메모 id를 해시해서 클라이언트에서 계산하면 매번 같은 값이 나오므로, Notion에 저장하지 않습니다.

### 2-4. Notion API 제한

| 항목 | 제한 | 이 프로젝트에 주는 영향 |
| --- | --- | --- |
| 요청 수 (연결 단위) | 일반 요금제 분당 180회(평균 초당 3회), Business·Enterprise 분당 600회 | 보드 조회를 반드시 캐시해야 합니다 |
| 요청 수 (워크스페이스 단위) | 워크스페이스의 모든 연결이 함께 쓰는 한도 | 다른 연동이 많은 워크스페이스는 피합니다 |
| 조회 한 번의 결과 | 최대 100개, `start_cursor`로 다음 페이지 요청 | 메모 300장이면 조회 3번이 필요합니다 |
| rich text 한 덩어리 | 2000자 | 500자 제한이라 문제없습니다 |
| 요청 본문 | 500KB, 블록 1000개 | 문제없습니다 |

한도를 넘으면 HTTP 429와 `rate_limited` 코드가 돌아오며, 응답의 `Retry-After` 헤더(초 단위)만큼 기다렸다가 다시 보내야 합니다. 쓰기 요청이 503을 받은 경우에는 이미 저장되었을 수도 있기 때문에, 무작정 다시 보내지 말고 먼저 조회해서 확인해야 중복 메모가 생기지 않습니다.
